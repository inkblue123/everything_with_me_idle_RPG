# ADR-0002：挖矿工具只加效率，不做硬门槛

- 日期：2026-10-23
- 状态：已接受
- 相关：`docs/plan/mining.md` M2

## 背景

`idea/idea5生活玩法设定.md` 对工具说了两遍相反的话：

- `:1109`「采集探索没有前提，伐木挖矿也没有前提，这俩虽然可以用斧头和镐子来约束，但是感觉不做这个限制会比较友好」
- `:1912`「挖矿的工具是镐子……战斗属性套用大锤，双手工具」

而现有实现事实上已经是"只加效率"：挖矿入口不检查工具，`MIN_attack` 默认 3，空手就能挖；
镐子的加成靠装备属性叠加（最终用的是 `MIN_damage_add` 这条直接加算通道，见 ADR 之外的计划 M5）。

## 决策

**空手可挖，镐子只加效率**。铁镐给挖矿伤害 +3（基础 3 → 装备后 6）与更慢的攻击间隔，不作为准入条件。

## 理由

1. 与现有实现一致，不需要改挖矿入口、界面提示、`GS_unlock_MIN` 的判定链。
2. 挖矿的解锁有两条路：铁匠铺力量测试（`mini_event.js:243`，发镐子）与支线奖励（`side_quest.js:24`，不发镐子）。
   如果设硬门槛，走支线解锁的玩家会"解锁了却挖不动"，还得再补一条发工具的链路。
3. 镐子的数值差异本身足够被感知（挖矿力翻倍），不需要靠准入来制造存在感。

## 后果

- 镐子是效率件，不是钥匙；玩家没镐子也能挖碎石岩层。
- 后续若要做"分档"（软矿空手可挖、硬矿必须镐子），需要给 `E_ore` 增加"硬度门槛"字段，
  并在挖矿入口加判定——属于新机制，不在本计划内。
- 铁镐的战斗属性走 `mining_tool` 的 L0 预设（`Enum_equipment.js:201-210`）：L0 近战按 `attack: max` 取到
  **攻击 4 / 精准 5 / 暴击 0**，比木剑（L1 normal，攻击 5）和木大锤（L1 max，攻击 8）都弱，定位仍是工具而非武器。
