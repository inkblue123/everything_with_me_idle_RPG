# 烹饪系统收尾记录（2026-10）

> **📦 只读归档**：烹饪系统在 2026-10-22 告一段落，后续开发转向其他系统。
> 本文记的是**这个阶段结束时它的真实状态**：做完了什么、还剩什么、为什么这么决策、哪些坑要记住。
> 现状以 `docs/SPEC.md` 为准；剩余待办以 `docs/roadmap.md` #3~#7 为准。

## 1. 告一段落时的状态

- **配方侧：闭环。** 7 条烹饪配方的解锁方式已改成「集齐材料自动解锁」，不再开局全送。
- **界面侧：闭环。** 烹饪菜品列表为空时有占位提示，不再是无解释的空白。
- **菜品 / 调味 / buff：已闭环**（2026-09-29，V0.3.9）。10 个成品效果、菜品 buff 前缀、调味配平、存读档修复均已落地。
- **未闭环的是「产出链」**：调料拿不到（COK_MS 空壳）、干制品没地方做（COK_MD 空壳）、烹饪工作台恒 0 级且不存档。详见 roadmap #3~#5。

## 2. 本轮做完的两件事

### 2.1 集齐材料自动解锁配方

- 数据：`Formula.auto_know_unlock_flag`（默认 `false`，由 `set_auto_know_unlock()` 开启）。首批只标**烹饪 7 条**，并把它们的 `initial_flag` 改为 `false`。
- 判定：玩家**还没有**该配方（`unknow`）+ 配方所需的每种材料都在**物品图鉴**点亮过（复用 `is_formula_all_materials_unlocked()`）→ 直接写 `know`。
- 触发：① 获得物品首次点亮图鉴时（`Player_get_item`）；② 读档末尾（`load.js` 的 `init_game` / `load_save`，用于旧存档按历史图鉴补齐）。
- 批量：`Player_get_formulas(ids)` 逐条写状态 + 逐条写 `get_formula` 日志，**只刷新一次**界面。
- 防御：旧存档缺 `library_save`（`item_library_data` 为 `undefined`）时直接跳过。

### 2.2 配方列表空态提示

- 触发条件：**玩家一条该技能配方都没有**（不是"被筛选条件过滤成空"）。
- 文案：烹饪「尚未学会任何烹饪配方，获得新的食材可能解锁新配方」；合成制造「未学会任何制作配方」。
- 样式：`.COK_formula_empty_tip` / `.SYN_formula_empty_tip`，居中 + `padding: 10px`，**不加 outline**（外层列表容器已有 2px 描边），不涉及 gap。

## 3. 当时定下的决策（避免以后重复讨论）

| 决策 | 结论 | 理由 |
|---|---|---|
| 解锁到哪个状态 | 直接 `know` | 与现有"图鉴口径=掌握"一致，改动最小 |
| 判定口径 | 图鉴点亮口径，**不看需求数量** | 与图鉴提示一致；代价是获得 1 条溪鱼会同时解锁「烤鱼串」和「大烤鱼串」 |
| 触发时机 | 获得物品时即时 + 读档追溯 | 玩家能看到"拿到材料→配方解锁"的因果 |
| 生效范围 | 数据里逐条开关，默认关 | 保住合成制造 20 条靠木工手册/事件解锁的价值 |
| `study` 状态 | 不处理 | 烹饪配方到不了 `study`（研究要求背包有该配方产物，产物只能靠该配方自己做） |
| 旧存档 | 追溯补齐 | 图鉴本来就有历史记录，补齐不需要额外字段 |
| 日志 | 复用 `get_formula`，追溯也逐条写 | 零新增 UI；一次最多 7 条，日志面板上限 10 条不溢出 |

## 4. 留给未来的坑

1. **烹饪配方永远到不了 `study`**：研究入口要求背包里有该配方的产物，而产物只能由该配方产出。以后若要开放"研究烹饪配方"，必须换一种研究条件。
2. **读档追溯会走一次界面刷新**（`updata_formula_value()`）。若玩家退出时正停在生活技能界面，读档瞬间会重建一次该界面。逻辑上 DOM 已建好，但这条路径以前读档不会走到，值得实测。
3. **空列表提示只判"有没有配方"**，不判"筛选后有没有结果"。后者保持原样（空白），避免出现"明明有配方却说未学会"的误导。
4. **图鉴口径依赖 `enums['Material_secon_type']` 等聚合枚举**：在无浏览器的脚本里必须先跑 `game_data_init()`，只调 `init_items()` 会让"任意蘑菇"这类集合判定失效（会打印"子类…不属于已知大类"）。
5. 游戏代码里有两处注释仍写着旧文档路径 `docs/plan_consumable_attribute.md`（`js/Data/Buff/Buff_dish.js:4`、`js/GameRun/consumable_manage.js:320`）。该文档已移到 `docs/archive/`，**基线代码未改名**，属已知项。
